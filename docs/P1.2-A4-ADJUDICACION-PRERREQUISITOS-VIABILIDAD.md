- `B06 = FOCAL_EXECUTION_VALIDATED` se conserva como adjudicación de una

  certifica suite completa ni gate global; la evidencia de aislamiento se

  preparación del harness para un nuevo run.
- `B10 = PARTIALLY_VERIFIED` se conserva. F-11/F-12 respaldan estáticamente
  que el tratamiento informativo se restringe a un nodeid y que otros fallos
  continúan bloqueando, pero la evidencia primaria de las siete pruebas F-09
  no se recuperó. Ninguna de esas fuentes autoriza repetirlas.
- La configuración de perímetro en el worktree no reemplaza policy externa y
  su estado modificado impide tomarla como identidad aprobada basándose solo
  en la rama/HEAD.
- La ausencia de evidencia del harness actual no convierte la arquitectura
  propuesta en un fallo funcional de P1.2. Solo impide adjudicarla como
  ejecutable, autorizada y trazable.

## 7. Brechas, prioridad y acción mínima

### Bloqueantes antes de considerar cualquier run futuro

1. Obtener autorización operacional externa, explícita y vigente para un
   alcance de run; identificar quién puede emitirla y verificarla. Una
   aprobación genérica dentro de esta conversación no sustituye el mecanismo
   autenticado requerido.
2. Resolver B-02–B-06: bootstrap/trust anchor externo, identidad transitiva,
   check-to-use y policy exacta del run, incluidos vigencia/revocación y
   límites. No elegir ni generar claves/autoridades por cuenta propia.
3. Resolver B-07–B-11 para el nivel de afirmación requerido: schema/ingesta,
   roles verificadores y observadores, expected inventory, recursos/retries
   y validación dinámica autorizada del boundary.
4. Identificar el candidato completo (incluido estado de worktree) que la
   autorización cubre y aplicar preflight/postflight del procedimiento
   aprobado sin alterar cambios preexistentes.
5. Resolver por separado la falta de salida primaria histórica si se pretende
   adjudicar el run antiguo. Un run futuro no recupera ni sustituye esa
   evidencia histórica.

### Próxima acción mínima permitida

No ejecutar. La siguiente acción debe ser una directiva específica que
identifique y documente, por canal externo, la resolución de prerrequisitos
aplicables y las autoridades/identidades/policies verificables. Solo después
de esa resolución puede evaluarse si corresponde emitir una autorización
separada de ejecución con alcance, preflight, límites, evidencia y postflight
concretos. Esta adjudicación no solicita ni asume esa autorización.
